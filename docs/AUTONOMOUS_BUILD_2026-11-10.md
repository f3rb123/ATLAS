# ATLAS V3 autonomous release candidate — 10 November 2026

This is the implementation/build handoff for 3.0.0rc1. The owner requested that
construction finish before further testing. Production certification is pending
the current-code acceptance gate. The previous 486739d package and its 214 tests
are preserved as historical evidence, not evidence for these later changes.

## Implemented workflow

1. The owner creates an engagement with a target, authorization reference,
   immutable scope, capability classes, request/time/token limits and preferences.
2. Discovery collects scoped pages, links, API descriptions and enabled fixed
   tool output. Every network operation passes through the trusted relay;
   responses become attributed evidence and shared specialist observations.
3. Eight initial specialist responsibilities use the same knowledge interface.
   Durable events activate bounded follow-up specialists. Source snapshots,
   reference skills, external intelligence and reviewed MCP resources supply
   additional context without granting execution authority.
4. Research can propose typed HTTP proof/control pairs or approved Python source
   harnesses with secure-patch controls. Separate verifier tasks collect fresh
   evidence and request an independent review before any confirmed finding.
5. The UI/CLI expose task progress, notes, unverified chains, evidence, operational
   warnings, pause/resume/stop and reports. Failed tool coverage makes completion
   partial instead of silently producing a clean bill of health.

## Capability boundaries

The native profiles are HTTPX, Katana, ffuf, Nuclei, subfinder, dnsx, naabu, Gau
and owner-managed Waybackurls. Eight licensed release binaries are pinned and
distributed. Waybackurls requires independently authorized owner provenance;
Gau provides default archive discovery. Scoped Amass/masscan result imports
retain external/unverified provenance; their raw engines are not executed.
Shodan, Censys v2, VirusTotal, FOFA and SecurityTrails have fixed read-only API
adapters and require the owner's corresponding credentials. MCP is limited to
reviewed resources and narrowly reviewed hostname tools.

Encrypted identities bind owned test accounts to origins/paths and run versions.
Explicit JSON login can obtain a run-bound encrypted bearer/cookie session.
Credentials stay outside model contexts and public evidence. Login refreshes,
HTTP redirects, DNS, passive indexes and TCP connects consume durable quotas.
Queued work checks stop/fence/deadlines; TCP discovery sends zero application
bytes. Destructive methods/actions, broad extraction and unrestricted shell are
outside the broker. Those controls do not impose the SBI smoke-only ceiling on
normal authorized campaigns.

Reflection, headers, scanner matches and CORS observations remain unverified
until their actual impact is demonstrated. This implementation does not claim
a browser exploit runner or universal coverage of every vulnerability class.
